1. About the application

TikTok-AI-Agent is a Windows desktop application and command-line tool for scanning a user-selected local video folder, preparing vertical MP4/H.264 video parts, making editable caption and hashtag drafts, optionally generating subtitles with locally installed Whisper.cpp software and a local model, and—when separately enabled and authorized—sending a selected video to TikTok through TikTok's official Login Kit and Content Posting API.

The application processes media on the user's computer. It does not provide a hosted video-processing service. TikTok login, authorization, creator-settings, upload, and post-status requests communicate with TikTok.

2. Requirements and account access

The user supplies and maintains a supported Windows computer and any required local software, including Python and FFmpeg/FFprobe. TikTok features require a TikTok account, a developer application configured by the operator, applicable TikTok product and scope approvals, and user authorization. Availability also depends on TikTok's current rules, API behavior, account settings, and limits. The operator has not represented that the developer application is approved for public posting.

4. Local processing and original files

Scanning reads supported files and records their path, size, and content hash to identify duplicate jobs. Processing reads the source video and writes separate processed output; the source file is not changed by normal processing. Optional subtitle generation uses a locally installed Whisper.cpp executable and an existing local model. Temporary audio is created on the computer for that operation.

The user should keep their own backups. Local files may be affected by the user's Windows account, storage, backup, antivirus, synchronization, or other software outside this application's control.

5. TikTok authorization and posting

TikTok Login Kit is used to obtain user authorization. The desktop authorization flow opens TikTok in the system browser, validates a single-use OAuth state value, uses PKCE, and receives the authorization response at the configured loopback address on the user's computer. The application stores returned access and refresh tokens locally in a Windows DPAPI-protected file. An app client secret entered through the hidden prompt can also be stored using current-user DPAPI. If the user instead configures a secret in an environment variable or .env file, the application does not encrypt that configuration file.

Publishing is disabled by default. Before a post, the application checks the stored video.publish grant and configured operator confirmations for app audit and scope approval, obtains current creator settings from TikTok, validates the video and duration, and requires the user to review the video and caption and confirm rights, music use, privacy, and the other selected post options. The user must give explicit per-post consent and type POST for that upload. A missing permission, approval confirmation, creator eligibility, valid setting, or consent blocks the post. Operator confirmation settings cannot grant TikTok approval or replace actual user authorization.

When the user confirms a post, the application sends the selected video and post information to TikTok, then polls TikTok for upload/post status. TikTok controls whether a post is accepted, processed, restricted, or made visible. No successful publication or particular audience reach is promised.

The user must follow TikTok's current developer terms, Content Posting API requirements, and content-sharing guidelines. The application does not automate TikTok's website or bypass API approval or restrictions.

6. Local cleanup

After TikTok confirms a successful publication, the application can record a local cleanup eligibility time, normally 24 hours later. Eligibility is not an automatic deletion guarantee. The current defaults disable cleanup (CLEANUP_ENABLED=false) and use dry-run mode (CLEANUP_DRY_RUN=true). The installed Windows scheduled task, if present, runs only run_agent.ps1 cleanup dry-run; that task reports eligible files and does not delete them.

Actual removal requires the user/operator to change the relevant cleanup settings and explicitly run the cleanup execution command. Deleting original input files has a separate opt-in setting (CLEANUP_SOURCE_FILES) and is disabled by default. Local cleanup does not remove a video already sent to TikTok or erase the application's database, caption drafts, or post history. The operator must verify these implementation details and current defaults before publishing this draft.
