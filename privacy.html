1. Scope and operation

TikTok-AI-Agent is a Windows desktop application and command-line tool. Its video scanning, conversion, segmentation, caption drafting, and optional transcription run on the user's computer. No project-hosted processing backend is part of the reviewed implementation. TikTok is contacted only for an OAuth flow or when the user invokes TikTok account/API functions; a video is sent to TikTok only through a separately authorized and consent-controlled posting operation.

This policy describes the local data handling and TikTok connections found in the project. It does not describe Windows, TikTok, or other software's independent data practices.

2. Data the application handles

Local video and job information

When scanning and processing, the application reads supported video files from the configured input folder. It records information needed for job tracking and duplicate prevention, including the source file path, SHA-256 content hash, file size, rights declaration, job and part identifiers, status, timestamps, expected duration, output path, and caption-file path. It creates processed video parts and may read an SRT subtitle file when one is present.

Captions and optional transcripts

The application saves editable caption drafts as local JSON files. A draft can contain a title derived from the source filename, caption text, selected hashtags, filename-based hashtag suggestions, and a review flag. If the user invokes offline subtitle generation and has configured a local Whisper.cpp executable and model, the application creates a temporary audio file locally and produces an SRT transcript locally. The project does not send that audio to a paid transcription API.

Database, events, and logs

The local SQLite database records job/part state and event history. Depending on the operation, records can include file paths, rights declarations, publication status, TikTok publish identifiers, error details, and timestamps. A local post log can contain a part ID, publish ID, status, failure reason, TikTok post IDs returned by TikTok, and the check time. If the Windows cleanup task is installed, it appends dry-run output and safe error details to data/cleanup-task.log; output can identify local files or paths. Credential-like values are redacted by the task logger, but logs remain local files that the user should protect.

OAuth credentials and tokens

TikTok OAuth uses the configured client key, redirect URI, requested scope, a temporary state value, and a PKCE challenge. The authorization code is exchanged with TikTok for user tokens. The local token store contains the access token, refresh token, TikTok account identifier (open_id), granted scopes, and token-expiration information. These tokens are stored in data/tiktok_tokens.dpapi protected with Windows DPAPI for the current Windows user. A client secret entered at the hidden OAuth prompt can be stored in data/tiktok_client_secret.dpapi using current-user DPAPI.

The client secret can alternatively be supplied using TIKTOK_CLIENT_SECRET in the process environment or the project's .env configuration. Those configuration values are not encrypted by the application; protect the Windows account and files accordingly. The client key, secret, access token, and refresh token must not be included in public documents, support logs, or screenshots.

TikTok creator settings and post data

During a publish attempt, the application requests current creator information/settings from TikTok, including the account name/username presented for review, posting availability, privacy choices, maximum video duration, and comment/Duet/Stitch availability. If the user proceeds, TikTok receives the selected video and post information such as caption, privacy level, interaction options, and applicable branded-content or AI-generated-content selections. TikTok returns upload/post identifiers and status information that the application records locally.

3. Why information is used

The application uses local video and metadata to discover work, prevent duplicate processing, create and validate output, prepare editable captions, enforce rights and review gates, and maintain job, publication, and cleanup status. OAuth data is used to authorize TikTok API calls and refresh an expired access token when the refresh authorization remains valid. Creator settings are fetched to check whether the account can post and to present current allowed options. Post-status information is used to record the result and, after confirmed publication, determine local cleanup eligibility.

4. Where information goes

Before the user initiates OAuth or TikTok API operations, media processing and optional transcription take place locally. For OAuth, the system browser connects to TikTok and the authorization callback returns to the configured local loopback address. OAuth/token and creator-settings requests are sent to TikTok's official API. If the user gives per-post consent and the application's safeguards pass, the selected video and its post information are uploaded to TikTok. TikTok then handles that content under TikTok's own policies.

The reviewed implementation does not include a separate project-operated cloud service or paid AI API. Users may independently store the project folder in a synchronized or backed-up location; Windows, backup, sync, antivirus, and other installed software may handle local files under their own settings.

5. Publishing choices and safeguards

TikTok publishing is disabled by default. A post is blocked unless the configured approval gates are enabled, the stored OAuth grant includes video.publish, current creator settings permit the requested post, the video validates, the caption has been reviewed, rights and music-use confirmations are recorded, and the user completes the application's review and explicit per-post consent steps. The user selects from the current creator privacy options and confirms applicable interaction/content settings. The user types POST to authorize that one upload. Configuration flags are operator confirmations; they do not create TikTok approval or permissions.

This local application does not make TikTok's approval, visibility, or eligibility decisions. TikTok may reject a request or restrict a post, including based on app audit status, account settings, limits, or platform rules.

6. Local storage and retention

The project stores data in its configured local folders, by default including input_videos, processed_parts, posting_queue, posted_logs, captions, and data. The database, captions, post history, credentials, and local video files remain on the computer unless the user separately uploads, syncs, backs up, or moves them. No general automatic expiry period for the local database, captions, post logs, tokens, or unprocessed source videos is identified in the reviewed implementation.

After a confirmed successful TikTok publication, the cleanup feature can record processed-output files as eligible after the configured retention period (24 hours by default). The current defaults are CLEANUP_ENABLED=false, CLEANUP_DRY_RUN=true, and CLEANUP_SOURCE_FILES=false. The installed hourly Windows task runs only run_agent.ps1 cleanup dry-run, so it reports eligibility without deleting files. Actual cleanup requires cleanup to be separately enabled, dry-run to be disabled, and an explicit cleanup execution command. Source-file deletion is independently gated and off by default. Cleanup acts on local files; it does not delete TikTok posts. Verify these settings and behaviors against the release before publication.

Users can remove local project files, including the DPAPI token and client-secret files, database, logs, captions, and video output, using Windows file-management tools. Removing tokens locally does not itself revoke the grant at TikTok; authorization should also be revoked through TikTok's account/app authorization controls. The application does not provide a hosted account or an identified in-app privacy-request portal. Deleting a local file is not represented as secure erasure and may not remove copies retained by backups or sync software.

TikTok's retention and deletion of information received through OAuth and Content Posting API are governed by TikTok's own policies and controls.

7. Security

OAuth tokens and a client secret saved through the hidden prompt are protected at rest with Windows DPAPI for the current Windows user. The application also applies credential redaction to supported error/log paths. DPAPI and redaction do not protect data from compromise of the Windows account, malware or processes running as that user, exposed environment variables, unprotected .env files, backups, or every possible third-party diagnostic. Keep Windows access restricted and do not share the project data folder or credentials.
